# Learning and Daily Update Workflow

This project is optimized for a busy schedule and a one-hour daily session.

## During the session

1. **Understand the physical problem.** What is the car doing in the real world?
2. **Derive only the mathematics needed today.** No decorative theory.
3. **Run working code quickly.**
4. **Change parameters or code and predict the effect before running it.**
5. **Validate with a plot, test, dimensional check, or limiting case.**
6. **Answer the review questions without looking at notes.**

## Notes policy

Do not spend the session copying long notes by hand. Daily notes are short and generated around:

- what was learned,
- equations that matter,
- code added,
- validation evidence,
- what is still unclear,
- 3–5 review questions.

## Engineering standard

A feature is not finished because it runs. It is finished when we can answer:

- What are its inputs and outputs?
- What physical assumptions does it make?
- What equations does it implement?
- What are the units?
- What breaks when assumptions fail?
- How do we know the implementation is correct?
